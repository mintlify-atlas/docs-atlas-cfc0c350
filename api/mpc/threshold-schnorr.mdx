## Overview

The `lindell22` package implements the Lindell 2022 threshold Schnorr signing protocol. This protocol allows multiple parties to jointly produce Schnorr signatures without reconstructing the private key.

**Location**: `pkg/mpc/tsig/tschnorr/lindell22/`

## Key Features

- Three-round signing protocol with commitment-based security
- Support for any MPC-friendly Schnorr variant
- Identifiable abort for detecting malicious signers
- Hash-based commitment scheme with Random Oracle security
- Compatible with Gennaro DKG for key generation

Contains public information shared among signing parties, including the joint public key and partial public keys.

## Usage Example

```go
import (
    "github.com/bronlabs/bron-crypto/pkg/mpc/tsig/tschnorr/lindell22"
    "github.com/bronlabs/bron-crypto/pkg/mpc/tsig/tschnorr/lindell22/keygen"
    "github.com/bronlabs/bron-crypto/pkg/mpc/tsig/tschnorr/lindell22/signing"
)

// 1. Create shard from DKG output
shard, err := keygen.NewShard(dkgOutput)

// 2. Create cosigner
cosigner, err := signing.NewCosigner(
    ctx,
    shard,
    fiatshamir.Name,
    schnorrVariant,
    prng,
)

// 3. Execute signing rounds
r1Out, err := cosigner.Round1()
r2In := exchangeMessages(r1Out) // Network exchange
r2Out, err := cosigner.Round2(r2In)
r3In := exchangeMessages(r2Out)
partialSig, err := cosigner.Round3(r3In, message)

// 4. Aggregate signatures
aggregator, err := signing.NewAggregator(publicMaterial, scheme)
signature, err := aggregator.Aggregate(partialSignatures, message)
```

## Security Considerations

- Uses hash-based commitment scheme, requiring Random Oracle assumption
- Provides identifiable abort: can detect which party produced invalid partial signature
- All parties must participate in all three rounds
- Nonce must be sampled with cryptographically secure randomness
- Session ID should be unique per signing session

## Protocol Rounds

**Round 1**: Each party commits to their nonce share
- Sample random nonce k_i
- Compute R_i = k_i · G
- Commit to R_i and broadcast commitment

**Round 2**: Open commitments and prove knowledge
- Open commitment to reveal R_i
- Provide zero-knowledge proof of knowledge of k_i
- Verify all received commitments and proofs

**Round 3**: Compute partial signatures
- Aggregate R = Σ R_i
- Compute challenge e = H(R || PK || m)
- Compute partial response s_i using Lagrange coefficients
- Broadcast partial signature (e, R, s_i)
