## Overview

The `boldyreva02` package implements the Boldyreva threshold BLS (Boneh-Lynn-Shacham) signature scheme. This protocol enables non-interactive threshold signatures on pairing-friendly curves, where each party can independently produce a partial signature that can be aggregated without further interaction.

**Location**: `pkg/mpc/tsig/tbls/boldyreva02/`

## Key Features

- Non-interactive signing (one round only)
- Support for both short key and long key variants
- Multiple rogue key prevention algorithms (Basic, MessageAugmentation, POP)
- Aggregatable signatures
- Pairing-based verification
- Compatible with Gennaro DKG for key generation

#### Aggregate

```go
func (A *Aggregator[PK, PKFE, SG, SGFE, E, S]) Aggregate(
    partialSigs network.RoundMessages[*boldyreva02.PartialSignature[SG, SGFE, PK, PKFE, E, S]],
    message []byte,
) (*bls.Signature[SG, SGFE, PK, PKFE, E, S], error)
```

Combines partial signatures from multiple cosigners into a single threshold signature. Verifies each partial signature against the corresponding partial public key before aggregation.

<ParamField path="partialSigs" type="network.RoundMessages[*PartialSignature]" required>
  The collection of partial signatures from cosigners
</ParamField>

<ParamField path="message" type="[]byte" required>
  The original message that was signed
</ParamField>

<ResponseField name="*bls.Signature">
  The aggregated BLS signature
</ResponseField>

<ResponseField name="error">
  Returns error with identifiable party ID tag if verification fails
</ResponseField>

**Verification Process**:
1. Checks quorum is authorized
2. Verifies each partial signature individually
3. Verifies POP signatures if using POP algorithm
4. Aggregates verified partial signatures
5. Returns final signature

## Rogue Key Prevention Algorithms

The Boldyreva02 scheme supports three rogue key prevention algorithms:

### Basic

```go
bls.Basic
```

No additional protection. Requires trusted setup or known private keys.

### Message Augmentation

```go
bls.MessageAugmentation
```

Augments the message with the public key: `message' = message || pk`

### Proof of Possession (POP)

```go
bls.POP
```

Requires each party to prove knowledge of their private key by signing their public key. Most commonly used in practice.

## Usage Example

```go
import (
    "github.com/bronlabs/bron-crypto/pkg/base/curves/pairable/bls12381"
    "github.com/bronlabs/bron-crypto/pkg/mpc/tsig/tbls/boldyreva02"
    "github.com/bronlabs/bron-crypto/pkg/mpc/tsig/tbls/boldyreva02/keygen"
    "github.com/bronlabs/bron-crypto/pkg/mpc/tsig/tbls/boldyreva02/signing"
    "github.com/bronlabs/bron-crypto/pkg/signatures/bls"
)

// 1. Create shard from DKG output
shard, err := keygen.NewShortKeyShard(dkgOutput)

// 2. Create BLS scheme with POP
curveFamily := bls12381.NewCurveFamily()
scheme, err := bls.NewShortKeyScheme(curveFamily, bls.POP)

// 3. Create cosigner
cosigner, err := signing.NewCosigner(shard, scheme)

// 4. Produce partial signature (non-interactive)
partialSig, err := cosigner.ProducePartialSignature(message)

// 5. Create aggregator
aggregator, err := signing.NewShortKeyAggregator(
    curveFamily,
    publicMaterial,
    bls.POP,
)

// 6. Aggregate partial signatures
signature, err := aggregator.Aggregate(partialSignatures, message)
```

## BLS Signature Variants

### Short Key Variant

- **Public keys**: G1 (48 bytes for BLS12-381)
- **Signatures**: G2 (96 bytes for BLS12-381)
- **Use case**: When public keys are transmitted frequently
- **Example**: Proof-of-Stake validators with fixed public keys

### Long Key Variant

- **Public keys**: G2 (96 bytes for BLS12-381)
- **Signatures**: G1 (48 bytes for BLS12-381)
- **Use case**: When signatures are transmitted frequently
- **Example**: Blockchain signatures, certificate chains

## Security Considerations

- **Non-interactive**: Each party can sign independently once they have the message
- **Pairing-based**: Security relies on hardness of discrete log in pairing-friendly groups
- **Rogue key attacks**: Must use appropriate prevention algorithm (POP recommended)
- **Identifiable abort**: Invalid partial signatures can be traced to specific parties
- **Deterministic**: No randomness needed during signing (optional message hashing)

## Performance Characteristics

- **Signing**: Very fast, single point multiplication
- **Verification**: Requires pairing operations (slower than ECDSA)
- **Aggregation**: Simple point addition
- **Signature size**: Constant, independent of threshold
- **Communication**: One round only (non-interactive)

## Error Handling

- **ErrInvalidArgument**: Invalid parameters provided
- **ErrFailed**: Operation failed (e.g., signature verification)
- Identifiable abort errors include `base.IdentifiableAbortPartyIDTag` for tracing malicious parties
